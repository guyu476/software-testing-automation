0开始之前：三条铁律

先把这节看完，能省你后面很多次"数据被我搞没了"。

铁律一：先查后改，先查后删

任何 UPDATE 和 DELETE，都先把 WHERE 条件放到 SELECT 里跑一遍。看看查出来的行是不是你想动的那几行。

-- 第一步：先看清楚要动谁
SELECT * FROM scores WHERE student_id = 1010;

-- 第二步：确认无误，再把 SELECT * 换成 UPDATE / DELETE
UPDATE scores SET score = 90 WHERE student_id = 1010;

为什么这么强调？因为 UPDATE scores SET score = 0; 这条语句语法完全正确、不会报错，但会把全表 47 条成绩全部改成 0。数据库不会问你"你确定吗"。忘了写 WHERE 是新人最高频的事故。

铁律二：数据库的数据是有类型的

数字就是数字，文字就是文字，写反了要么报错、要么查不到。

SELECT * FROM scores WHERE score > 90;        -- 对：score 是数字类型
SELECT * FROM scores WHERE score > '90';      -- 能跑，但依赖数据库帮你隐式转换，别这么写

铁律三：NULL 不是 0，也不是空字符串

NULL 的意思是"这里没有值"，比如吴涛的数学成绩，因为他缺考了，不是考了 0 分。

-- 错！查不出任何数据。注意：它不报错，只是安静地返回 0 行
SELECT * FROM scores WHERE score = NULL;

-- 对，这才是"没成绩"的写法
SELECT * FROM scores WHERE score IS NULL;

-- 有成绩的
SELECT * FROM scores WHERE score IS NOT NULL;

这是初学者最容易踩的坑，没有之一。记住：和 NULL 比较只能用 IS NULL / IS NOT NULL，不能用 = 或 !=。

最危险的地方在于：写 = NULL 不会报错。它会正常运行、安静地返回 0 行，看起来就像"库里确实没这样的数据"。如果你不知道这个坑，就会误以为"真没这条记录"，然后往完全错误的方向排查半天。上面三条语句都跑一遍、对比返回的行数，你会记得很牢。

在 Navicat 里怎么跑

教程里所有的 SQL 都是写完整、可以直接复制去跑的，以分号 ; 结尾就是一条完整语句。

如果运行时报 1064 语法错误，八成是因为只粘了后半截。最常见的就是漏掉开头的 SELECT ... FROM ...，只把 WHERE ... 那一段粘了过去——单独一个 WHERE 不是完整语句，数据库读不懂。复制时从 SELECT 开头选起。

  1. 左侧双击展开 school 库 → 右键 → 新建查询
  2. 把教程里的 SQL 粘进去
  3. 点工具栏的 运行（或按 Ctrl+R / F8），结果出现在下方
  4. 想只跑其中一条？用鼠标把那条语句选中，再点运行，就只执行选中的部分

1SELECT：我要哪几列

查询的起点。先搞清楚"取哪些列、从哪张表取"。

语法

SELECT 列1, 列2, 列3
FROM 表名;

就这两个关键字。SELECT 后面写你要哪些列，FROM 后面写从哪张表。

示例一：查全部列

SQL
SELECT * FROM students;

* 是通配符，代表"所有列"。自己看数据的时候方便，但正式写查询时别用——你只要 3 列却拖出 6 列，既慢又乱。

结果（12 行，只展示前 4 行）
student_idnamegenderbirth_dateclass_namephone
1001张伟男2006-03-12一班13800001111
1002王芳女2006-05-20一班13800002222
1003李强男2006-01-08一班13800003333
1004刘敏女2006-07-15二班13800004444

示例二：只要某几列

SELECT student_id, name, class_name
FROM students;

列名用逗号隔开，最后那个列名后面不要加逗号——这是新手最常见的语法错误。

示例三：给列起别名 AS

SELECT
    student_id  AS 学号,
    name        AS 姓名,
    class_name  AS 班级
FROM students;
结果
学号姓名班级
1001张伟一班
1002王芳一班

AS 只是给列改个显示名字，不会改数据库里的真实字段名。AS 其实可以省略不写（SELECT name 姓名 也行），但建议写上，可读性好。

顺手学个习惯：SQL 关键字用大写（SELECT / FROM / WHERE），表名列名用小写。数据库本身不区分大小写，这纯粹是给人看的，方便一眼分清"哪些是语法、哪些是我自己的东西"。

2WHERE：筛出我要的行

实际工作里 90% 的查询都带条件。这节是重点，慢慢看。

基础比较运算

SELECT * FROM scores WHERE score > 90;      -- 大于
SELECT * FROM scores WHERE score >= 90;     -- 大于等于
SELECT * FROM scores WHERE score < 60;      -- 小于（不及格）
SELECT * FROM scores WHERE score != 60;     -- 不等于，也可以写 <>
SELECT * FROM students WHERE class_name = '一班';   -- 文字要用单引号

文字必须加单引号。写 WHERE class_name = 一班 数据库会以为你在拿它跟一个叫"一班"的列比较，直接报错 Unknown column。这里用的是英文单引号 '，不是中文的 ‘，也不是双引号。

AND / OR：多个条件

-- 男生 并且 在二班
SELECT * FROM students WHERE gender = '男' AND class_name = '二班';

-- 一班 或者 二班
SELECT * FROM students WHERE class_name = '一班' OR class_name = '二班';

-- 混合：一班的女同学
SELECT * FROM students WHERE class_name = '一班' AND gender = '女';

AND 和 OR 混用时一定要加括号。因为 AND 的优先级比 OR 高，A OR B AND C 会先算 B AND C，结果可能跟你想的完全不同。

-- 想表达：(一班或二班) 的男生
WHERE (class_name = '一班' OR class_name = '二班') AND gender = '男'

IN：在某个范围里挑

条件里有好几个"或"的时候，用 IN 比一堆 OR 清爽得多。

-- 这两个写法结果完全一样
SELECT * FROM students WHERE class_name = '一班' OR class_name = '二班' OR class_name = '三班';

SELECT * FROM students WHERE class_name IN ('一班', '二班', '三班');

-- 反过来：不在这些班级里的
SELECT * FROM students WHERE class_name NOT IN ('一班', '二班');

BETWEEN：在区间里（含两端）

-- 60 到 80 分之间，包含 60 和 80
SELECT * FROM scores WHERE score BETWEEN 60 AND 80;

-- 等价于
SELECT * FROM scores WHERE score >= 60 AND score <= 80;

-- 日期也能这么筛
SELECT * FROM scores WHERE exam_date BETWEEN '2026-06-16' AND '2026-06-18';

BETWEEN 是闭区间，两端都包含。很多人下意识以为不含右端，写出来的条件就差了那么一条数据。

LIKE：模糊匹配

记不住完整内容时用。% 代表"任意多个字符"，_ 代表"任意一个字符"。

SELECT * FROM students WHERE name LIKE '张%';      -- 姓张的
SELECT * FROM students WHERE name LIKE '%伟';      -- 名字以"伟"结尾
SELECT * FROM students WHERE name LIKE '%小%';     -- 名字里带"小"
SELECT * FROM students WHERE phone LIKE '138%';    -- 手机号 138 开头

% 放在开头（'%伟'）会导致索引失效、全表扫描。数据量大时会明显变慢。自己练习无所谓，工作中要留意。

IS NULL：找"没有值"的

-- 没留电话的学生
SELECT * FROM students WHERE phone IS NULL;

-- 缺考的记录
SELECT * FROM scores WHERE score IS NULL;

-- 留了电话的（IS NULL 的反面）
SELECT * FROM students WHERE phone IS NOT NULL;

在你的数据里，students 表里 1010 吴涛的电话是空的；scores 表里吴涛的数学成绩是空的（缺考）。

  1. 查询三班的所有学生。
  2. 查询分数大于 90 的所有成绩记录。
  3. 查询男生里在二班的学生。
  4. 查询分数在 60 到 80 之间的成绩。

  7. 查询语文（C01）或数学（C02）的成绩记录。

  9. 查询 class_name 是「一班」或「二班」的女同学。（提示：括号）

1. 三班的学生
SELECT * FROM students WHERE class_name = '三班';

3 行：赵丽（1007）、黄鹏（1008）、周婷（1009）。

2. 分数大于 90

SELECT * FROM students WHERE gender = '男' AND class_name = '二班';

只有杨磊（1006）一个人。

4. 60 到 80 分
SELECT * FROM scores WHERE score BETWEEN 60 AND 80;
5. 姓张的
SELECT * FROM students WHERE name LIKE '张%';

2 行——1001 和 1011 都叫张伟，但学号不同、班级不同。这是刻意的：查人的时候永远靠 ID，别靠姓名。

用 OR 写也对：WHERE course_id = 'C01' OR course_id = 'C02'。两条路都得会，因为看别人的 SQL 时会遇到。

注意用 < 不包含 60 分；如果你的及格线是"60 分以下算挂"，那 60 分本身要算及格，这里是对的。先把结果记下来，第 3 节会讲 ORDER BY。

3ORDER BY 与 LIMIT

排序、取前几名、翻页。排行榜类的需求全靠这两个。

ORDER BY：排序

-- 按分数从高到低（降序 DESC）
SELECT * FROM scores ORDER BY score DESC;

-- 按分数从低到高（升序 ASC，默认就是这个）
SELECT * FROM scores ORDER BY score ASC;
SELECT * FROM scores ORDER BY score;      -- 不写 ASC 也一样

-- 按班级排序，同班内再按学号排
SELECT * FROM students ORDER BY class_name ASC, student_id ASC;

多个排序字段用逗号隔开，先按第一个排，第一个相同了才看第二个。

NULL 排在哪？

SELECT * FROM scores ORDER BY score DESC;
结果（47 行，摘开头和结尾）
idstudent_idcourse_idscore
391009C0298.0
411009C0394.5
…………
291006C0348.0
431010C02NULL

MySQL 里 NULL 被当成最小值，所以升序时排最前，降序时排最后。想让它去别的位置，得单独控制（进阶，先不管）。

LIMIT：只取前几条

-- 分数最高的 3 条
SELECT * FROM scores ORDER BY score DESC LIMIT 3;

-- 语法：LIMIT 从第几条开始, 取几条
-- 翻页：第 1 页（前 5 条）
SELECT * FROM scores ORDER BY score DESC LIMIT 0, 5;

-- 第 2 页（第 6-10 条）
SELECT * FROM scores ORDER BY score DESC LIMIT 5, 5;

-- 第 3 页（第 11-15 条）
SELECT * FROM scores ORDER BY score DESC LIMIT 10, 5;

注意起始位置从 0 开始数。LIMIT 5, 5 的意思是"跳过前 5 条，取接下来 5 条"。翻页公式：LIMIT (页码-1) * 每页条数, 每页条数。

LIMIT 通常要配 ORDER BY 用。不排序的话，数据库返回的顺序是随机的、不保证稳定的，"取前 3 名"就失去了意义。

书写顺序（重要）

SELECT   列
FROM     表
WHERE    条件
ORDER BY 排序
LIMIT    条数;

这个顺序是固定死的，不能调换。WHERE 必须在 ORDER BY 前面，ORDER BY 必须在 LIMIT 前面。写反了直接语法报错。

练习 3 · 排序与分页
  1. 把所有成绩按分数从高到低排列。
  2. 把学生按班级升序排列，同班内按学号升序排列。
  3. 查出分数最高的 3 条成绩记录。
  4. 查出成绩排名第 4 到第 6 的记录（用 LIMIT 的第二种写法）。
  5. 查出三班的学生，按出生日期从早到晚排列。
  6. 查出分数最低的那条记录是谁的、哪一科。
对答案
1. 分数降序
SELECT * FROM scores ORDER BY score DESC;
2. 班级 + 学号
SELECT * FROM students ORDER BY class_name, student_id;

一班排完才排二班。注意班级是按中文排序的，结果顺序是"一班、三班、二班、四班"还是"一班、二班、三班、四班"？跑跑看——中文排序取决于字符集，这一点跟你想的可能不一样。

3. 最高 3 条
SELECT * FROM scores ORDER BY score DESC LIMIT 3;

98.0（周婷·数学）、97.0（周婷·生物）、96.0（周婷·语文）。周婷霸榜了。

4. 第 4 到第 6 名
SELECT * FROM scores ORDER BY score DESC LIMIT 3, 3;

跳过前 3 条，取 3 条。LIMIT 3, 3 第一个 3 是"跳过几条"，不是"从第 3 条开始"。

5. 三班按年龄
SELECT * FROM students WHERE class_name = '三班' ORDER BY birth_date;

出生日期越早 = 年龄越大，所以升序就是"大的在前"。

6. 最低分那条
SELECT * FROM scores ORDER BY score LIMIT 1;

升序排第一条。注意：升序时 NULL 会跑到最前面，所以这条查出来的"最低分"其实是那条缺考的 NULL 记录（id=43，吴涛的数学）。如果想排除缺考，要加 WHERE score IS NOT NULL。这个小坑自己撞一次比看十遍都记得牢。

SELECT * FROM scores WHERE score IS NOT NULL ORDER BY score LIMIT 1;

这样才是真正的"最低分"：48.0，杨磊的英语。

4聚合函数与 GROUP BY

从"看每一行"升级到"看整体"。统计、报表、看板都靠它。

五个必会的聚合函数

SELECT COUNT(*)    FROM students;   -- 数有多少行 → 12
SELECT SUM(score)  FROM scores;     -- 求和
SELECT AVG(score)  FROM scores;     -- 平均分
SELECT MAX(score)  FROM scores;     -- 最高分
SELECT MIN(score)  FROM scores;     -- 最低分

聚合函数是"把多行揉成一个数"。注意 AVG 和 COUNT 会自动忽略 NULL：

SELECT COUNT(*)        FROM scores;  -- 47，数的是"有多少行"
SELECT COUNT(score)    FROM scores;  -- 46，数的是"有多少个非 NULL 的分数"
SELECT AVG(score)      FROM scores;  -- 除的是 46，不是 47

-- 想知道差了多少行（谁没成绩）
SELECT COUNT(*) - COUNT(score) AS 缺考条数 FROM scores;

COUNT(*) 和 COUNT(列名) 的区别是面试常考题，也是理解 NULL 的关键。COUNT(*) 数行数，COUNT(列名) 只数该列非 NULL 的。

GROUP BY：先分组，再统计

"每门课的平均分""每个班有多少人"——这类需求就是 GROUP BY。

-- 每个班有多少人
SELECT class_name, COUNT(*) AS 人数
FROM students
GROUP BY class_name;
结果
class_name人数
一班3
二班3
三班3
四班3

怎么理解 GROUP BY：数据库先按 class_name 把 12 行分成几堆，然后对每一堆单独算一次 COUNT(*)，最后每堆输出一行。

-- 每门课程的平均分、最高分、选课人数
SELECT
    course_id,
    COUNT(*)      AS 考试人次,
    ROUND(AVG(score), 1) AS 平均分,
    MAX(score)    AS 最高分,
    MIN(score)    AS 最低分
FROM scores
GROUP BY course_id;

ROUND(值, 小数位数) 用来保留小数，不然平均分会是一长串。

一条必须记住的规则

SELECT 里出现的列，要么在 GROUP BY 里，要么被聚合函数包着。

-- 错：name 既没分组也没聚合，数据库不知道该给你哪一行
SELECT class_name, name, COUNT(*) FROM students GROUP BY class_name;

-- 对
SELECT class_name, COUNT(*) FROM students GROUP BY class_name;

MySQL 在宽松模式下可能不报错，会随便挑一行给你，但那个结果毫无意义。写 SQL 时养成这个习惯：先想清楚"我要按什么分组"，再想"每组要算什么"。

HAVING：给分组结果筛条件

WHERE 筛的是每一行，HAVING 筛的是分完组之后的每一堆。

-- 平均分高于 85 的课程
SELECT course_id, ROUND(AVG(score), 1) AS 平均分
FROM scores
GROUP BY course_id
HAVING AVG(score) > 85;

WHERE 和 HAVING 的分工：

WHERE score IS NOT NULL → 先剔掉缺考的行，再分组算平均。
HAVING AVG(score) > 85 → 先分组算完平均，再把平均分不达标的那组扔掉。

顺序是 WHERE → GROUP BY → HAVING → ORDER BY → LIMIT。

-- 组合起来：只算有成绩的记录，找出平均分高于 80 的课程，按平均分从高到低
SELECT
    course_id,
    COUNT(*)             AS 人数,
    ROUND(AVG(score), 1) AS 平均分
FROM scores
WHERE score IS NOT NULL
GROUP BY course_id
HAVING AVG(score) > 80
ORDER BY 平均分 DESC;
练习 4 · 聚合与分组
  1. 统计学生总人数。
  2. 统计成绩表里有多少条考试记录。
  3. 统计全校各科成绩的平均分、最高分、最低分。
  4. 统计每个班男生、女生各有多少人。（提示：按两个字段分组）
  5. 统计每门课程的选课人数和平均分，按平均分从高到低排。
  6. 找出平均分高于 85 分的课程。
  7. 统计成绩表里缺考的记录有几条。
对答案
1. 学生总数
SELECT COUNT(*) AS 学生总数 FROM students;

12

2. 考试记录数
SELECT COUNT(*) AS 记录数 FROM scores;

47

3. 各科统计
SELECT
    ROUND(AVG(score), 1) AS 平均分,
    MAX(score)           AS 最高分,
    MIN(score)           AS 最低分
FROM scores;

这里没写 GROUP BY，因为要的是"全校一张总表"，不是"每科一行"。不要习惯性加 GROUP BY——不加就是全部数据算一次。

4. 每班男女各多少人
SELECT class_name, gender, COUNT(*) AS 人数
FROM students
GROUP BY class_name, gender
ORDER BY class_name, gender;

按两个字段分组，就是"班级 + 性别"组合起来分堆。注意：某个班里如果没有女生，那一组根本不会出现，不是显示 0。这是 GROUP BY 的常见困惑点。

5. 每门课人数与平均分
SELECT
    course_id,
    COUNT(*)             AS 选课人数,
    ROUND(AVG(score), 1) AS 平均分
FROM scores
GROUP BY course_id
ORDER BY AVG(score) DESC;

ORDER BY 后面可以直接写聚合函数，也可以写别名 ORDER BY 平均分 DESC。

6. 平均分高于 85 的课程
SELECT course_id, ROUND(AVG(score), 1) AS 平均分
FROM scores
GROUP BY course_id
HAVING AVG(score) > 85;
7. 缺考条数
SELECT COUNT(*) AS 缺考条数 FROM scores WHERE score IS NULL;

1 条（吴涛的数学）。

5JOIN：把分开的表拼起来

单表查询的天花板就在这。真实工作里几乎每个查询都是多表。这节最需要动脑，也最值得。

为什么需要 JOIN

看个实际问题：「查周婷的语文成绩，要显示她的名字、课程名和分数」。

名字在 students，课程名在 courses，分数在 scores。三张表，一次查不完。

为什么当初不把名字、课程名都塞进成绩表？因为那样张伟会重名重复 4 次、语文会重复 40 多次，改一个任课老师要改 40 行——这叫数据冗余，是不行的。所以数据分开存，要用的时候靠关联字段拼回来。JOIN 就是干这个的。

INNER JOIN：只保留两边都匹配上的

看 scores 表，里面只存了学号 1001，没有姓名。JOIN 就是让数据库拿着这个 1001 去 students 表里把张伟找出来。

SELECT
    s.name,
    s.class_name,
    sc.course_id,
    sc.score
FROM scores sc
JOIN students s ON sc.student_id = s.student_id;

语法拆解：

FROM scores sc — 主表是成绩表，sc 是我给它起的表别名（不写别名也行，但要写全 scores.student_id，很啰嗦）。

JOIN students s ON ... — 要把 students 表接进来，别名 s。

ON sc.student_id = s.student_id — 连接条件，告诉数据库两边靠哪个字段对应。这个字段就叫关联字段（外键）。

结果（47 行，前 4 行）
nameclass_namecourse_idscore
张伟一班C0188.5
张伟一班C0292.0
张伟一班C0376.0
张伟一班C0485.0

三张表连起来

再接一次 JOIN，把课程名和老师也带出来。

SELECT
    s.name            AS 姓名,
    c.course_name     AS 课程,
    c.teacher         AS 老师,
    sc.score          AS 分数
FROM scores sc
JOIN students s ON sc.student_id = s.student_id
JOIN courses  c ON sc.course_id  = c.course_id
ORDER BY s.name, c.course_name;

规律就是：JOIN 一次接一张表，每接一张都要写 ON 说清楚靠什么字段对上。四张表就 JOIN 三次。

LEFT JOIN：以左表为主，找不到也保留

INNER JOIN（就是 JOIN）只保留两边都匹配上的行。这有个后果：徐萌（1012）一条成绩都没有，所以在上面那个查询结果里她整个人都不见了。

LEFT JOIN 的规则是：左边表的数据全都保留，右边表没有对应数据的地方就填 NULL。

SELECT
    s.student_id,
    s.name,
    sc.course_id,
    sc.score
FROM students s
LEFT JOIN scores sc ON s.student_id = sc.student_id
ORDER BY s.student_id;
结果（47 + 徐萌 = 48 行，摘录）
student_idnamecourse_idscore
1001张伟C0188.5
…………
1012徐萌NULLNULL

这就是 LEFT JOIN 的经典用法——找"缺了什么"：

-- 一条成绩都没参加考试的学生
SELECT s.student_id, s.name, s.class_name
FROM students s
LEFT JOIN scores sc ON s.student_id = sc.student_id
WHERE sc.id IS NULL;      -- 右边没匹配上，说明这个人没成绩

这个方法一定要记住：LEFT JOIN + WHERE 右表字段 IS NULL = 找出左表里有、右表里没有的数据。

实际工作中超常用：找出没下过单的会员、没有分配负责人的订单、没有选任何课的学生……都是这个套路。

练习 5 · 多表连接
  1. 查出每个学生的姓名和分数（成绩表连学生表）。
  2. 查出周婷所有科目的成绩，要显示姓名、课程名、分数。
  3. 查出语文这一科的所有成绩：姓名、班级、分数，按分数从高到低。
  4. 查出一条成绩都没有的学生。（LEFT JOIN + IS NULL）
  5. 统计每门课程的选课人数和平均分，显示课程名称而不是课程编号。
  6. 算出每个学生的总分和平均分，按总分从高到低排。
  7. 找出有选课记录、但学生表里查不到对应学号的脏数据。（这次反着来：以 scores 为主表做 LEFT JOIN）
对答案
1. 姓名 + 分数
SELECT s.name, sc.score
FROM scores sc
JOIN students s ON sc.student_id = s.student_id;
2. 周婷的各科成绩
SELECT s.name, c.course_name, sc.score
FROM scores sc
JOIN students s ON sc.student_id = s.student_id
JOIN courses  c ON sc.course_id  = c.course_id
WHERE s.name = '周婷';

6 行（她六科全考了）。注意：这里用 s.name = '周婷' 只是练习方便——真实业务里必须用学号查，因为重名是存在的（你的表里就有两个张伟）。

3. 语文成绩排行
SELECT s.name AS 姓名, s.class_name AS 班级, sc.score AS 分数
FROM scores sc
JOIN students s ON sc.student_id = s.student_id
JOIN courses  c ON sc.course_id  = c.course_id
WHERE c.course_name = '语文'
ORDER BY sc.score DESC;
4. 没参加考试的学生
SELECT s.student_id, s.name, s.class_name
FROM students s
LEFT JOIN scores sc ON s.student_id = sc.student_id
WHERE sc.id IS NULL;

1 行：徐萌（1012，四班）。

5. 每门课的人数与平均分
SELECT
    c.course_name        AS 课程,
    c.teacher            AS 老师,
    COUNT(sc.id)         AS 选课人数,
    ROUND(AVG(sc.score), 1) AS 平均分
FROM courses c
LEFT JOIN scores sc ON c.course_id = sc.course_id
GROUP BY c.course_id, c.course_name, c.teacher
ORDER BY AVG(sc.score) DESC;

这里用 LEFT JOIN，是为了让没人选的课也能出现在结果里（显示人数 0）。你现在的数据里六门课都有人选，所以看不出差别——但这正是业务上最需要留意的细节。注意 COUNT(sc.id) 而不是 COUNT(*)：没人选课时 COUNT(*) 会算出 1（因为左表那一行还在），COUNT(sc.id) 才会正确给 0。

另外 GROUP BY 后面把 course_name、teacher 都写上了——严格模式（ONLY_FULL_GROUP_BY）下必须这样，否则报错。

6. 每个学生的总分和平均分
SELECT
    s.student_id,
    s.name,
    COUNT(sc.id)            AS 考试科数,
    SUM(sc.score)           AS 总分,
    ROUND(AVG(sc.score), 1) AS 平均分
FROM students s
LEFT JOIN scores sc ON s.student_id = sc.student_id
GROUP BY s.student_id, s.name
ORDER BY SUM(sc.score) DESC;

用 LEFT JOIN 是为了让"一科没考"的学生也留在名单里。但注意：缺考的 NULL 不计入 SUM 和 AVG，所以吴涛的数学缺考不会拉低他的平均分——这是好是坏取决于业务定义。做测试的你要习惯问这个问题："这个口径对吗？"

另外排序时 NULL 会跑到最后（降序），所以徐萌在末尾。

7. 找出孤儿数据
SELECT sc.*
FROM scores sc
LEFT JOIN students s ON sc.student_id = s.student_id
WHERE s.student_id IS NULL;

现在应该返回 0 行——说明数据是干净的，没有孤儿记录。想让这条查询真查出点东西？去第 9 章练习里自己造一条试试。

6INSERT：新增数据

增删改三兄弟里最简单的。学会它，你就能自己造测试数据了。

语法

INSERT INTO 表名 (列1, 列2, 列3) VALUES (值1, 值2, 值3);

三个关键点：列和值的个数必须一样、顺序必须一一对应、文字要加单引号。

示例一：插一个学生

INSERT INTO students (student_id, name, gender, birth_date, class_name, phone)
VALUES (1013, '孙悦', '女', '2006-05-05', '四班', '13800007788');

-- 插完立刻验证
SELECT * FROM students WHERE student_id = 1013;

新增数据后一定要立刻查一次。这是习惯，不是可选项。你以为插进去了，可能字段错位、可能中文乱码——不查你不会知道。

示例二：一次插多条

值和值之间用逗号隔开，一条语句插多行，比写多条 INSERT 快得多。

INSERT INTO scores (student_id, course_id, score, exam_date) VALUES
(1013, 'C01', 85.0, '2026-06-15'),
(1013, 'C02', 90.0, '2026-06-16'),
(1013, 'C03', 78.5, '2026-06-17');

示例三：只插部分列

没写出来的列会取默认值，而 scores.score 和 students.phone 允许为空，所以就是 NULL。

INSERT INTO students (student_id, name, gender, class_name)
VALUES (1014, '郑好', '男', '五班');

SELECT * FROM students WHERE student_id = 1014;
-- birth_date 和 phone 都是 NULL

关于自增主键

scores 表的 id 是 AUTO_INCREMENT，所以插入时完全不用管它，数据库自动给。如果你想手动指定 id，也可以，但没必要。

-- 让数据库自己编号
INSERT INTO scores (student_id, course_id, score, exam_date)
VALUES (1013, 'C04', 88.0, '2026-06-18');

7UPDATE：改数据

最容易出事故的一条语句。看完这节你会理解为什么老手改数据前都要先 SELECT。

语法

UPDATE 表名 SET 列1 = 新值1, 列2 = 新值2 WHERE 条件;

SET 后面写"改成什么"，WHERE 后面写"改哪些行"。

示例一：标准流程（先查后改）

-- 第一步：先看清楚这一行现在什么样
SELECT * FROM students WHERE student_id = 1010;

-- 第二步：确认真的是他，再改
UPDATE students SET phone = '13900001111' WHERE student_id = 1010;

-- 第三步：改完再查一次确认
SELECT * FROM students WHERE student_id = 1010;

三步走，一步都别省。第一步的成本是 2 秒钟，第二步写错的成本可能是 2 小时。

示例二：一次改多个字段

UPDATE students
SET phone = '13900002222',
    class_name = '五班'
WHERE student_id = 1010;

示例三：基于原值计算

可以用原来的值算新值。比如班里批改有误，所有成绩统一加 5 分：

-- 注意：这条会影响李强的 4 条成绩记录
UPDATE scores SET score = score + 5 WHERE student_id = 1003;

-- 想改回去
UPDATE scores SET score = score - 5 WHERE student_id = 1003;

凡是做批量 UPDATE，先跑一次 SELECT 看行数。

SELECT COUNT(*) FROM scores WHERE student_id = 1003;  -- 4 条，心里有数了再改

示例四：把值改成 NULL

UPDATE students SET phone = NULL WHERE student_id = 1010;

直接写 = NULL 是可以的（在 SET 里），但要跟 WHERE 里的 IS NULL 区分开。

危险演示：忘了写 WHERE

UPDATE students SET phone = NULL;

这条语句语法完全正确、不会报错、不会警告，但它会把 12 个学生的电话全部清空。数据库非常"听话"，它不会猜你的意图，也不会问"你确定吗"。

养成肌肉记忆：写完 UPDATE，先回头看一眼有没有 WHERE。

如果真改错了怎么办

三条路，按优先级：

  1. 开事务（进阶）：START TRANSACTION; 改 → 查看结果 → 不对就 ROLLBACK; → 对就 COMMIT;。改错了还能退回来。
  2. 练习时重跑脚本：把 01_setup.sql 再跑一遍，数据恢复原样。
  3. 生产环境改错了：立刻停手、上报，靠备份恢复。千万不要自己在生产库上反复尝试补救——那通常会把事情变得更糟。

7. 思考题的答案

会"改掉" 3 行（四班的 3 个学生），但值没有任何变化——因为本来就已经是「四班」了，把 4 改成 4 而已。

8DELETE：删数据

不可逆。这节的重点不是语法，是心态。

语法

DELETE FROM 表名 WHERE 条件;

就这一条。语法简单到没有任何门槛，所以风险全在 WHERE 上。

示例一：删单条记录

-- 先查
SELECT * FROM scores WHERE id = 48;

-- 再删
DELETE FROM scores WHERE id = 48;

-- 确认
SELECT * FROM scores WHERE id = 48;   -- 应该 0 行

为什么用 id 删而不是用 student_id 删？因为 id 是主键，唯一，只会命中一行。如果用 WHERE student_id = 1013 删，何雨的三条成绩会全被删掉——可能不是你要的。

删单条数据时，优先用主键定位。

示例二：按条件批量删

-- 删掉所有不及格的记录（慎重）
SELECT * FROM scores WHERE score < 60;
DELETE FROM scores WHERE score < 60;

-- 删掉 2026-06-20 那天的考试记录
DELETE FROM scores WHERE exam_date = '2026-06-20';

示例三：删一个学生和他所有的成绩

因为咱们故意没建外键约束，所以删除顺序得你自己保证。合理顺序是先删子表、再删主表：

-- 先删他的成绩（子表）
DELETE FROM scores WHERE student_id = 1014;

-- 再删他的人（主表）
DELETE FROM students WHERE student_id = 1014;

如果只删了主表会怎样？学生没了，但他的成绩记录还留在 scores 里，学号指向一个不存在的人——这就是脏数据 / 孤儿记录，正是第 5 章练习 7 查的东西。

如果当初建了外键约束，数据库会直接拦住你，报"违反外键约束"，根本删不掉。这就是外键的价值：把"人必须自己记得顺序"变成"数据库强制保证"。

等你把增删改练顺了，建议回头给 scores 表补上外键，再试试删除，能直观看到约束的作用。

危险演示：忘了写 WHERE

DELETE FROM scores;    -- 47 条成绩，一次性全没

和 UPDATE 一样，这条语句不报错、不警告、不问你是否确定。DELETE 是没法"撤销"的——没有回收站。

所以规矩要更严：先写 SELECT，看着结果确认无误，再把 SELECT * 改成 DELETE。

顺带认识：TRUNCATE

TRUNCATE TABLE scores;   -- 清空整张表，比 DELETE FROM scores 快得多

区别：TRUNCATE 会清空整表、重置自增 id，而且不能加 WHERE（想按条件删只能用 DELETE）。日常练习里没必要用它。

SELECT * FROM scores WHERE student_id = 1012;   -- 0 行，她没有任何成绩
DELETE FROM scores WHERE student_id = 1012;     -- 执行了，但一条没删

结论："删除 0 行"不会报错。数据库只会淡淡地说 0 rows affected。所以测试时"执行成功"绝不能作为"功能正确"的判断依据——必须验证数据实际变成什么样。这是新手测试最容易犯的错。

3. 删马超的缺考记录
DELETE FROM scores WHERE student_id = 1016 AND score IS NULL;

两个条件用 AND 连起来，确保只删这一条。如果只写 WHERE score IS NULL，会把吴涛那条也一起删掉。

4. 完整删除郑好
SELECT * FROM scores WHERE student_id = 1014;
DELETE FROM scores   WHERE student_id = 1014;   -- 先子表
DELETE FROM students WHERE student_id = 1014;   -- 再主表

-- 验证
SELECT * FROM students WHERE student_id = 1014; -- 0 行
SELECT * FROM scores   WHERE student_id = 1014; -- 0 行
5. 删 06-20 的记录
SELECT * FROM scores WHERE exam_date = '2026-06-20';   -- 王芳的生物、陈静的生物、周婷的生物
SELECT COUNT(*) FROM scores WHERE exam_date = '2026-06-20';
DELETE FROM scores WHERE exam_date = '2026-06-20';

应该是 3 条（三张 C06 生物的成绩都在 06-20）。

6. 思考题的答案

删了成绩，学生还在。因为是"子表引用主表"，删子表的数据不会影响主表。students 里张伟完好，只是他变成了"一个没参加任何考试的学生"。

反过来删学生，成绩会残留。因为没建外键约束，scores 里那 4 条记录的 student_id = 1001 会变成指向空气的孤儿记录。你可以用第 5 章练习 7 那条 LEFT JOIN 查询把它揪出来——会从 0 行变成 4 行。

这就是"数据完整性"问题的真实面目：单看哪张表都正常，一关联就露馅。建议你真动手试一遍，然后用脚本重跑恢复数据。

9实战：测试岗的数据题

前面都是练语法，这节练"用 SQL 解决实际问题"。软件测试岗最常用的几类数据库操作都在这。

测试为什么必须会 SQL

  • 造数据——功能测一半发现缺测试数据，等开发造不如自己插
  • 校验数据——界面显示"总分 356"，你得去库里算一遍对不对
  • 定位问题——接口返回不对，先查库看是"数据本来就不对"还是"数据对但显示错了"
  • 数据清洗——测试环境被搞乱了，自己修回来

最后一条是重点思维：界面错了，可能是数据错了，也可能是数据没错但代码算错了。这两者的定位方向完全不同。会查库的人，能一句话说清是哪个环节的问题。

套路一：找异常数据（数据校验）

假设有个校验规则：分数必须在 0 到 100 之间。怎么写 SQL 去验证库里有没有违反的数据？

-- 先查 0-100 之外的记录
SELECT * FROM scores WHERE score < 0 OR score > 100;

-- 再换个角度：查 0-100 之内的，两边数字加起来应该等于总数
SELECT COUNT(*) FROM scores WHERE score BETWEEN 0 AND 100;  -- 应该 = 47

-- 如果两个数对不上，就说明有脏数据漏进去了

「正着查一遍、反着查一遍、数字对得上」——这是数据校验的基本思路。单查一边容易漏。

套路二：找孤儿数据（引用完整性）

-- 成绩表里有、学生表里查不到学号 → 孤儿记录
SELECT sc.*
FROM scores sc
LEFT JOIN students s ON sc.student_id = s.student_id
WHERE s.student_id IS NULL;

-- 反向：学生表里有、但从来没参加过考试
SELECT s.*
FROM students s
LEFT JOIN scores sc ON s.student_id = sc.student_id
WHERE sc.id IS NULL;

套路三：找重复数据（唯一性）

-- 同一个学生、同一门课，本该只有一条成绩，看看有没有重复
SELECT student_id, course_id, COUNT(*) AS 重复条数
FROM scores
GROUP BY student_id, course_id
HAVING COUNT(*) > 1;

HAVING COUNT(*) > 1 是查重复数据的万能句式，换掉 GROUP BY 的字段就能查各种维度的重复。

套路四：数量对账（一致性）

-- 学生表里的总人数
SELECT COUNT(*) AS 学生总数 FROM students;

-- 成绩表里出现过的去重学号（有多少人真的考过试）
SELECT COUNT(DISTINCT student_id) AS 有成绩的人数 FROM scores;

-- 差出来的就是没参加考试的人
SELECT COUNT(DISTINCT student_id) FROM scores;  -- 11
SELECT COUNT(*) FROM students;                  -- 12

COUNT(DISTINCT 字段) 是"去重后计数"，一个学生考了 6 科也只算 1 个人。这个函数非常常用，一定要记住。

练习 9 · 综合实战

这组题没有标准答案顺序，写法可能不止一种。重点是思路对。

  1. 造一条脏数据再揪出来：往 scores 表插一条分数为 120 的记录（学号 1015，课程 C05，日期 2026-06-19）。然后用"找异常数据"的 SQL 把它查出来。最后删掉它。
  2. 造一条孤儿数据：插一条 student_id = 9999 的成绩（这个学生在 students 表里不存在）。用"找孤儿数据"的 SQL 把它揪出来，再删掉。
  3. 检查重复：给同一个学生（1015）同一门课（C01）再插一条成绩。然后用查重复的 SQL 找出这条重复数据。
  4. 数量对账：求出"学生总数"和"参加过考试的人数"，算出差几个，并用查询列出具体是哪几个学生没考试。
  5. 业务题：导出补考名单——所有分数低于 60 的学生，显示学号、姓名、班级、课程名、分数，按分数从低到高排。
  6. 业务题：算出每个学生的平均分，只显示平均分高于 85 的，按平均分降序，显示姓名和平均分（保留 1 位小数）。
  7. 业务题：找出至少有两门课不及格的学生。先自己想清楚思路再看答案。
对答案
1. 造脏数据并揪出来
INSERT INTO scores (student_id, course_id, score, exam_date)
VALUES (1015, 'C05', 120, '2026-06-19');

SELECT * FROM scores WHERE score < 0 OR score > 100;

DELETE FROM scores WHERE score = 120;

删的时候用 WHERE score = 120 就够精准了，因为正常情况下不会有 120 这样的分数。但真实环境里更稳的写法是先查出 id，再用 id 删，避免误伤。

2. 造孤儿数据
INSERT INTO scores (student_id, course_id, score, exam_date)
VALUES (9999, 'C01', 70, '2026-06-19');

SELECT sc.* FROM scores sc
LEFT JOIN students s ON sc.student_id = s.student_id
WHERE s.student_id IS NULL;

DELETE FROM scores WHERE student_id = 9999;

这就是为什么外键约束重要。如果有外键，第 1 条 INSERT 就失败了——数据库直接拦住"给不存在的人记录成绩"这件事。

3. 检查重复
INSERT INTO scores (student_id, course_id, score, exam_date)
VALUES (1015, 'C01', 90.0, '2026-06-15');

SELECT student_id, course_id, COUNT(*) AS 重复条数
FROM scores
GROUP BY student_id, course_id
HAVING COUNT(*) > 1;

应该查出 (1015, C01) 重复 2 条。

注意这里的要点：数据库允许这条重复插入（因为主键是自增 id，不是"学号+课程号"）。如果业务规则是"一个学生一门课只能有一条成绩"，那这就应该是个约束，而现在的表设计漏了它。做测试时发现这类缺口，是很高价值的输出。

修法有两种：把 (student_id, course_id) 建为唯一索引（数据库强制），或者让代码层校验。前者更可靠——代码可能被绕过，约束不会。

4. 数量对账
SELECT COUNT(*) AS 学生总数 FROM students;

SELECT COUNT(DISTINCT student_id) AS 参考人数 FROM scores;

-- 具体是谁没考
SELECT s.student_id, s.name, s.class_name
FROM students s
LEFT JOIN scores sc ON s.student_id = sc.student_id
WHERE sc.id IS NULL;

12 - 11 = 1 人，是徐萌（1012）。

5. 补考名单
SELECT
    s.student_id    AS 学号,
    s.name          AS 姓名,
    s.class_name    AS 班级,
    c.course_name   AS 课程,
    sc.score        AS 分数
FROM scores sc
JOIN students s ON sc.student_id = s.student_id
JOIN courses  c ON sc.course_id  = c.course_id
WHERE sc.score < 60
ORDER BY sc.score;

这道题是本节最"真实"的一道——三表连接 + 条件 + 排序，工作里 80% 的业务查询就是这个形状。

6. 平均分高于 85 的学生
SELECT
    s.name                  AS 姓名,
    ROUND(AVG(sc.score), 1) AS 平均分
FROM scores sc
JOIN students s ON sc.student_id = s.student_id
GROUP BY s.student_id, s.name
HAVING AVG(sc.score) > 85
ORDER BY AVG(sc.score) DESC;

这里用 JOIN 而不是 LEFT JOIN，因为"平均分高于 85"本身就要求有成绩，没成绩的人不在讨论范围。用哪个取决于业务口径——"没考试的人算不算 0 分"这个问题的答案，会改变结果。做测试时这就是典型的"需求歧义点"，要提出来。

7. 至少两门课不及格

思路拆解：第一步先"每人每门课是否不及格" → 第二步"按人分组数出来几条" → 第三步"筛出 ≥ 2 的"。

SELECT
    s.student_id,
    s.name,
    COUNT(*) AS 不及格科数
FROM scores sc
JOIN students s ON sc.student_id = s.student_id
WHERE sc.score < 60
GROUP BY s.student_id, s.name
HAVING COUNT(*) >= 2
ORDER BY COUNT(*) DESC;

关键在于 WHERE 先筛出不及格的行，GROUP BY 再按人分组数。这个"先过滤再分组"的思维模式，是 SQL 里最值钱的东西。

李强和杨磊应该都会上榜（注意如果你前面做过"低于 60 改成 60"那道题，结果就变了——这正是数据库练习的特点：你的操作会改变后续题目的答案。乱了就把脚本重跑一遍）。

附速查表

写 SQL 时对着这张表找，不用回去翻。

语句结构

SELECT   要哪些列
FROM     哪张表
JOIN     另一张表 ON 关联条件
WHERE    每行的过滤条件
GROUP BY 按什么分组
HAVING   分组的过滤条件
ORDER BY 按什么排序
LIMIT    取几条;

这个顺序是固定的，不能调换。

常用条件写法

=  !=  <  >  <=  >=          比较
AND  OR  NOT                    与、或、非（注意括号）
IN ('A','B')  /  NOT IN (...)    在 / 不在某个范围
BETWEEN 60 AND 80               区间（含两端）
LIKE '张%'  /  LIKE '%伟'        模糊匹配
IS NULL  /  IS NOT NULL         空值判断（不能用 = NULL）

聚合函数

COUNT(*)          数行数
COUNT(列名)        数该列非 NULL 的个数
COUNT(DISTINCT 列) 去重后计数
SUM(列名)          求和
AVG(列名)          平均（忽略 NULL）
MAX(列名)  MIN(列名) 最大 / 最小

常用函数

ROUND(值, 2)                 保留 2 位小数
CONCAT(值1, 值2)             字符串拼接
IFNULL(值, 替换值)           值为 NULL 时用替换值（做报表常用）
DATE(日期时间)               只取日期部分
YEAR(日期)  MONTH(日期)      取年 / 月

增删改

-- 新增
INSERT INTO 表 (列1, 列2) VALUES (值1, 值2);

-- 修改
UPDATE 表 SET 列 = 新值 WHERE 条件;

-- 删除
DELETE FROM 表 WHERE 条件;

写 SQL 的检查清单

  1. WHERE 写了吗？（UPDATE / DELETE 前必问）
  2. 文字加单引号了吗？
  3. NULL 用 IS NULL 而不是 = NULL 了吗？
  4. SELECT 里的列，要么在 GROUP BY 里、要么在聚合函数里了吗？
  5. JOIN 的 ON 条件写对了吗？连接字段类型一致吗？
  6. 要排序的话，ORDER BY 加了吗？
  7. 改完 / 删完，验证过了吗？
